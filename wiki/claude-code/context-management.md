# Claude Code 上下文管理

> 研究日期：2026-04-26  
> 状态：实战总结  
> 研究员：凯戈 + Claude

---

## 一、为什么上下文管理是核心技能

Claude Code 的上下文窗口是有限资源。管理不好：
- 会话中途被截断，丢失工作状态
- Claude 开始"忘事"，回答质量下降
- 需要重新解释背景，效率损耗大

管理好：
- 单次会话可以完成更复杂的任务
- 跨会话保持连续性，不需要每次重头解释
- Claude 始终有足够上下文给出高质量回答

## 二、上下文状态判断

```
< 50%   — 正常，随意工作
50-75%  — 注意，避免大量引入新文件
75%+    — 危险，准备 /compact 或新开会话
```

Claude Code 状态栏会显示上下文使用比例（桌面 App 更直观）。

## 三、核心操作手册

### 3.1 引用文件（最常用）

```bash
# 直接引用，省去「帮我读 X」来回
@~/project/src/main.py

# 引用多个文件
@~/project/src/main.py @~/project/README.md

# 引用整个目录（谨慎，会消耗大量上下文）
@~/project/src/
```

**原则**：只引用当前任务真正需要的文件，不要一次引入整个项目。

### 3.2 压缩上下文

```bash
/compact
```

- 上下文 75%+ 时使用
- Claude 会把对话历史压缩成摘要，释放空间
- **会损失部分细节**，执行前确认当前任务不依赖早期的具体内容

### 3.3 清空上下文

```bash
/clear
```

- 切换到完全不相关的新任务时用
- 比 /compact 更彻底，不保留历史摘要
- 适合：同一 CLI 会话内切换项目

### 3.4 续接上次会话

```bash
claude -c
```

- 恢复上次会话的上下文和工具状态
- **凯戈常用场景**：前一个会话因上下文满载中断，第二天接着干
- 配合计划文件（`~/.claude/plans/`）使用效果最好

### 3.5 进入计划模式

```
Shift + Tab（连按两次）
```

- 在执行复杂任务前，先让 Claude 输出完整计划
- Claude 会列出所有步骤，用户确认后再执行
- **凯戈适用场景**：多步骤任务开始前，防止中途跑偏

## 四、上下文效率技巧

### 4.1 精准提问

差：「帮我看看这个项目有什么问题」  
好：「@src/auth.py 第 45 行的 JWT 验证逻辑有什么安全问题？」

### 4.2 任务分批

一次会话不要试图完成所有事情。用计划文件记录进度，分多次会话执行。

### 4.3 CLAUDE.md 减少重复说明

把每次都要说的背景信息写进 CLAUDE.md，自动加载，不占用对话上下文。

### 4.4 善用 memory 系统

跨会话的重要信息存入 memory（`~/.claude/projects/*/memory/`），Claude 会自动在相关对话中调取。

## 五、凯戈的上下文管理实战

**开工时**：
1. `claude -c`（续接）或 `claude`（新开）
2. 读 INDEX.md + 当前项目的 WIP.md / dev_log.md
3. 确认任务后开工

**中途**：
- 上下文 75%+ → `/compact`
- 任务切换 → `/clear`
- 会话即将满载 → 把进度写入计划文件，新开会话继续

**收工时**：
- 更新 WIP.md / dev_log.md
- 更新 kaige-brain/INDEX.md
- git push
